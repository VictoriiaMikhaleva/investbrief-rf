# Учёт сплитов (закон проекта)

События живут только в `data/split-events.json`. Расчёты и UI читают их через `split-events.js`.  
Новое дробление попадает в продукт **после записи в справочник**, не по эвристике «минус 90%».

## 1. Экономика позиции

Сплит не меняет экономическую стоимость позиции.

Пример 1:10:

- до: 1 акция × 3000 ₽ = 3000 ₽
- после: 10 акций × 300 ₽ = 3000 ₽

То же для 1:100: 1 × 15 000 ₽ = 100 × 150 ₽.

## 2. Поле `ratio`

`ratio` — сколько **новых** акций получается из **одной старой**.

- 1:10 → `ratio: 10`
- 1:100 → `ratio: 100`

Обратный сплит (`type: reverse`) в v1 не применяется к ценам и дивидендам.

## 3. Доходность

Для расчётов доходности (в том числе `totalReturn12m`):

- цены **до** сплита приводятся к текущей шкале (делить на `ratio`);
- дивиденды на 1 акцию **до** сплита приводятся к текущей шкале;
- текущие цены и выплаты **после** сплита не меняются.

Если окно 12 месяцев пересекает событие из справочника, используется split-adjusted расчёт.  
Если скорректировать нельзя — fallback «сплит» / «н/д», **не** сырой −90% / −99%.

## 4. График «Цена»

- «с учётом сплита» — сопоставимая adjusted-динамика (ISS candles.close уже в текущей шкале).
- «фактическая цена» — цена одной акции на дату (`restoreRawPriceFromAdjustedForSplits`).
- Adjusted цену нельзя показывать как обычную фактическую без подписи и переключателя.

Переключатель виден, только если split из справочника попадает в видимый период графика.

## 5. Портфель

- `portfolio` JSON нельзя менять автоматически.
- `qty` / `avgPrice` нельзя переписывать без подтверждения пользователя.
- Будущий split-aware расчёт — **виртуальный** слой поверх пользовательских лотов.
- Если шкала лота неясна (купили до сплита, qty не пересчитан) — `partial` / warning, не уверенный результат.
- Автокоррекции позиций нет.

## 6. Агент

- День сплита не создаёт тревожный `day-up` / `day-down`.
- Остальные сигналы (оборот, неделя и т.д.) не отключать.

## 7. ОФЗ

- Сплиты акций к ОФЗ не применять.
- Купоны и НКД не корректировать.

## 8. Новые события

1. Подтвердить факт по MOEX / раскрытию эмитента.
2. Добавить строку в `data/split-events.json` (ticker, aliases, isin, effectiveDate, ratio, type, note, source; при ссылке — `sourceUrl`).
3. Не угадывать сплит только по дневному −90%.
4. Подозрительный скачок без записи в справочник можно пометить как warning-кандидат, но не считать сплитом.

Поля справочника расширяемые. Не дублировать одно и то же событие. Сомнительные даты не добавлять.
