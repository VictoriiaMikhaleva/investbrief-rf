# Карта данных InvestBrief × MOEX

**Дата:** 24.08.2026  
**Источник анализа:** код `investbrief-rf` (`moex.js`, `markets.js`, `news.js`, `agent.js`, `analytics*`, `ofz.js`, `pif.js`, `portfolio.js`, `data/*.json`, CI `update-market-data`).

**Цель:** отделить жёсткую зависимость от MOEX ISS от снимков, end-of-day и событий/раскрытия.

---

## Короткий вывод

Продуктивность держится на трёх слоях:

1. **Учёт портфеля и статьи** — без MOEX.
2. **Новости / агент «зоны внимания»** — ближе к событиям, чем к тикам.
3. **Котировки, оборот сессии, YTM/купоны ОФЗ и live BPIF** — ядро ISS.

Перевод сессионного слоя на EOD почти не бьёт по «сводке дня», но режет ощущение «в моменте» у топ‑20 и меток портфеля.

| Корзина | Оценка по карте |
|---------|-----------------|
| Строго live MOEX | ~9 поверхностей |
| Уже с snapshot | ~6 |
| Кандидаты в EOD | ~8 |
| События / раскрытие | ~7 |

---

## Легенда стратегий

| Метка | Смысл |
|-------|--------|
| **Строго MOEX** | Live ISS критичен |
| **MOEX + fallback** | Live preferred, snapshot спасает UI |
| **→ EOD** | Можно закрытие / дневной снимок |
| **→ события/раскрытие** | Продуктивность на новостях / IR |
| **Без MOEX** | Независимый источник |

## 2. Четыре корзины решения

### 2.1. Точно MOEX-зависимые (строго)

Нельзя «просто выключить ISS» без замены поставщика:

- Intraday топ‑20 `VALTODAY`
- Live last / day% по произвольному тикеру (аналитика, портфель)
- ОФЗ: YTM, дюрация, НКД, купонный календарь `bondization`
- Live last / iNAV биржевых ПИФ
- Поиск бумаг через ISS `q=` без своего справочника
- `getAnalytics` / watchdog freshness (сервер тоже бьёт в MOEX)

**Продуктовый смысл:** «рынок сейчас». Без ISS нужен другой market-data vendor или сознательный отказ от intraday.

### 2.2. Можно без MOEX уже сейчас

- Ключевая ставка ЦБ
- Новостная лента RSS (export новостей MOEX ≠ ISS quotes)
- Каталог ПИФ / раскрытие / архив (`pif-*.json`, ЦБ)
- Образовательные статьи
- Портфель как учёт (лоты, продажи, PnL от введённых цен)
- Настройки, watchlist, auth sync (Firebase)
- US-рынок (Yahoo)

Home-макро и топ уже падают на `data/*.json` при outage — UI «серый, но живой».

### 2.3. Перевести на end-of-day

Почти без потери продуктивности сводки:

- IMOEX close + дневное изменение
- FX: курс ЦБ на дату (уже есть fallback)
- Оборот IMOEX по торговым дням
- Топ бумаг по обороту **за день** (не VALTODAY)
- Свечи / история цены / оборот в аналитике
- Каталог ОФЗ + EOD-параметры в `ofz.json`
- Mark-to-market портфеля на закрытии
- Див‑KPI и `totalReturn12m` (и так не intraday)

CI уже пишет снимки примерно каждые 5 минут — для EOD-режима достаточно 1× после клиринга + пометка «на ДД.ММ».

### 2.4. Заменить событиями / раскрытием

Сохраняет «зачем смотреть» без тиков:

- Новостные briefs + календарь эмитента / IR
- Дивиденды: решения СД / собрания / e-disclosure + patches
- Агент: зона = событие (отчёт, отсечка, новость), цена — вторичный чек
- ОФЗ: Минфин / параметры выпуска из раскрытия; цена — опционально
- ПИФ: СЧА/пай из раскрытия УК / ЦБ вместо iNAV
- «Что проверить» в карточке агента — уже event-first UX

Это ближе к заявленному статусу сервиса (информационно-аналитический), чем к терминалу котировок.

## 3. Продуктивность: сценарии

| Сценарий | Сохраняется | Деградирует | Вердикт |
|----------|-------------|-------------|---------|
| Только EOD MOEX (снимки после сессии) | Сводка дня, аналитика 5л, портфель-учёт, ОФЗ-обзор, ПИФ-каталог, новости | Топ «прямо сейчас», live mark в торговые часы, iNAV | Ок для investbrief.ru как сводки |
| Без ISS: RSS + раскрытие + ЦБ | Новости, ставка, ПИФ-реестр, статьи, структура портфеля, див-календарь (частично) | Любые цены / обороты / YTM / агент по цене | Сервис событий; нужна честная плашка |
| Гибрид: EOD ISS + live RSS/агент-события | Почти весь продукт; агент сильнее на новостях | Сессионный азарт топ‑20 | **Лучший баланс** риска MOEX / пользы |
| Как сейчас: live ISS + snapshot fallback | Максимум «рынка сейчас» + устойчивость на Pages | Юридический/операционный вес бренда MOEX, нагрузка ISS | Оптимум для терминальности |

## 5. Приоритет, если снижать MOEX-зависимость

| Приоритет | Действие |
|-----------|----------|
| **P0** | Dual-режим в продукте: «сводка EOD» vs «сессия» — не смешивать VALTODAY с закрытием без подписи |
| **P1** | Дивиденды и агент — усилить event/disclosure path (уже частично: patches, briefs) |
| **P2** | Портфель и графики аналитики — EOD marks по умолчанию; live quote — opt-in |
| **P3** | ОФЗ YTM/bondization и BPIF iNAV — последний рубеж ISS; менять только с альтернативным поставщиком или честным EOD-снимком параметров |

---

## 6. Вне скоупа этой карты

YDB user-sync API есть, но UI сейчас на Firebase. Это не влияет на карту рыночных данных MOEX.
